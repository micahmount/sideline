```bash

npm run build      # tsc -b && vite build (outputs to dist/)
```

### Dev server access

The dev server uses a self-signed HTTPS cert (auto-generated by `@vitejs/plugin-basic-ssl`) so that COOP/COEP headers are honored on all origins:

| Method | URL | Notes |
|---|---|---|
| Desktop (local) | `https://localhost:5173/` | localhost secure context — accept self-signed cert |
| Phone / LAN | `https://192.168.x.x:5173/` | Accept self-signed cert warning in browser |

COOP/COEP headers (`Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp`) are required by sqlite-wasm for SharedArrayBuffer. Browsers only honor these on secure contexts (HTTPS or localhost).

## Architecture rules (non-negotiable)

- **Event sourcing (ADR-002):** Never mutate game state directly. Always append `GAME_EVENT` records. Current state is derived by replaying events.
- **SQLite in Web Worker only (ADR-001):** `@sqlite.org/sqlite-wasm` runs off the main thread. Never import it on the main thread. Communicate via `postMessage`.
- **COOP/COEP headers** required for SharedArrayBuffer (sqlite-wasm). Already set in `vite.config.ts` — don't remove.
- **No auto-execution (ADR-003, ADR-005):** Sub queue and suggestion engine surface info; the coach always confirms.
- **`@sqlite.org/sqlite-wasm` excluded from Vite pre-bundling** (`optimizeDeps.exclude` in vite.config.ts).
- **`GAME_EVENT` rows are append-only** — never UPDATE or DELETE. `events.ts` enforces this.

## IDs

Use `randomId()` from `src/lib/randomId.ts` which wraps `crypto.randomUUID()` with a fallback for non-secure contexts. SQLite uses TEXT primary keys.
