# Production Deployment

Sideline is a fully static PWA. No server-side rendering or Node.js runtime is required — any static file server will work.

## Required HTTP Headers

The following headers are **required** for cross-origin isolation (SharedArrayBuffer, needed by `@sqlite.org/sqlite-wasm`):

| Header | Value |
|---|---|
| `Cross-Origin-Opener-Policy` | `same-origin` |
| `Cross-Origin-Embedder-Policy` | `require-corp` |

These are already configured in the Vite dev server (`vite.config.ts`), but must be replicated in your production hosting.

### Content Security Policy (recommended)

```http
Content-Security-Policy: default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; worker-src 'self' blob:
```

Key notes:
- `'wasm-unsafe-eval'` is required for sqlite-wasm's WASM compilation.
- `worker-src 'self' blob:` allows the SQLite Web Worker to load.
- `style-src 'unsafe-inline'` is needed for Tailwind (no CSS-in-JS, but Vite injects hot-reload in dev; in production the CSS is a static file).

## SPA Fallback

Since Sideline uses client-side routing (React Router), the server must serve `index.html` for any non-asset path. This is known as **SPA fallback** or **history API fallback**.

### nginx

```nginx
server {
    listen 443 ssl;
    server_name sideline.example.com;

    root /var/www/sideline/dist;
    index index.html;

    # Required for SharedArrayBuffer
    add_header Cross-Origin-Opener-Policy "same-origin" always;
    add_header Cross-Origin-Embedder-Policy "require-corp" always;

    # Optional: CSP
    add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; worker-src 'self' blob:" always;

    # SPA fallback
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Cache static assets
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

### Caddy

```caddy
sideline.example.com {
    root * /var/www/sideline/dist
    
    # Required for SharedArrayBuffer
    header {
        Cross-Origin-Opener-Policy "same-origin"
        Cross-Origin-Embedder-Policy "require-corp"
    }

    # Optional: CSP
    header Content-Security-Policy "default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; worker-src 'self' blob:"

    # SPA fallback
    try_files {path} /index.html

    # Cache static assets
    @static {
        path *.js *.css *.svg *.ico *.woff2 *.json
    }
    header @static Cache-Control "public, immutable"
    encode gzip
}
```

### Cloudflare Pages

1. **Build command:** `npm run build`
2. **Build output directory:** `dist`
3. **Root path:** `/`

**Headers** (add via `_headers` file or Cloudflare dashboard):

```txt
/*
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Embedder-Policy: require-corp
  Content-Security-Policy: default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; worker-src 'self' blob:
```

**SPA fallback** — Cloudflare Pages does this automatically when you set the root path to `/`.

**Cache rules** — add a page rule for `/assets/*` with cache level "Standard" and Edge Cache TTL of 1 year.

### Vercel

Add a `vercel.json` at the project root:

```json
{
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "Cross-Origin-Opener-Policy", "value": "same-origin" },
        { "key": "Cross-Origin-Embedder-Policy", "value": "require-corp" }
      ]
    }
  ],
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

Vercel's built-in Next.js/Vite preset is not needed; use the default "Other" framework.

## Build

```bash
npm install
npm run build     # outputs to dist/
```

The `dist/` directory contains everything needed for deployment:

```
dist/
├── index.html
├── assets/
│   ├── index-*.js
│   ├── index-*.css
│   └── ...
├── icons/
│   └── *.svg
├── manifest.webmanifest
└── sw.js           # Workbox-generated service worker
```

## PWA Asset Caching

The service worker (generated by `vite-plugin-pwa` / Workbox) caches:

| Strategy | Assets |
|---|---|
| **Precache (on install)** | JS, CSS, HTML, SVG icons, JSON manifest, WOFF2 fonts |
| **CacheFirst (runtime)** | sqlite-wasm WASM/JS from `https://sql.org` (1-year TTL) |

The service worker is only active when served over **HTTPS** (or `localhost`). Without HTTPS the PWA features (install prompt, offline support) will not work.

## Environment Notes

- **Node.js:** Not needed at runtime. Build step only.
- **Server-side rendering:** None. Sideline is a fully client-side SPA.
- **Database:** SQLite runs entirely in the browser (Origin Private File System). No backend database is needed.
- **Offline:** Once loaded, the app works without a network connection. The service worker serves cached assets and OPFS persists data locally.
- **HTTPS is required** for:
  - Service Worker registration
  - `navigator.storage` (OPFS)
  - PWA install prompt
